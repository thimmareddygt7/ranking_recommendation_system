What this project is

Teaching a shopping site to stop treating every visitor the same.

Most sites show every visitor the same "Popular Right Now" shelf. This project builds a system that looks at what one specific shopper has actually clicked, carted, and bought — then quietly reorders the shelf just for them.

Built on 2.75 million real shopping events from an e-commerce site (Retailrocket). No made-up data, no toy dataset — the same kind of messy, real-world logs a live store would produce.

How it actually works

Two steps, run one after another for every shopper. No step requires a human to hand-pick anything.

1

Narrow the catalog down

Think of a huge warehouse with a hundred thousand products. Step one is a fast first pass — it looks at everything this shopper has interacted with before, and everything similar shoppers liked, and pulls out the 100 items most likely to be relevant. It's built for speed, not precision.

The technical version
Implicit ALS (Alternating Least Squares) matrix factorization, trained on weighted implicit feedback (view / add-to-cart / purchase). Produces dense user and item vectors; candidates are retrieved by similarity score.
2

Put the best ones first

Step two takes just those 100 shortlisted items and carefully reorders them — this is the step that actually learned, from millions of real examples, what makes an item worth showing first. It's slower per item, but there are only 100 items left to sort, so it's still fast overall.

The technical version
LightGBM gradient-boosted trees trained with a LambdaMART (lambdarank) objective — a learning-to-rank loss, not standard classification. Features include the retrieval score, item conversion rate, and the shopper's recent activity.
3

Handle shoppers we've never seen

Brand-new visitors have no history to learn from, so personalizing for them would just be guessing. Instead, they get the genuinely popular items — a safe, sensible default until they've clicked around enough to personalize for.

Why this matters for a real business

This isn't an academic exercise — it's the same pattern behind the "Recommended for you" row on nearly every shopping site.

  • Better recommendations mean more sales without more traffic. Showing the right item first, instead of a generic bestseller list, is a direct lever on conversion rate — no marketing spend required.
  • New visitors are never left with a blank page. The cold-start fallback means even a shopper with zero history still sees a sensible, tested set of items.
  • The system checks itself over time. A drift monitor compares how the model's recommendations shift week to week, so a sudden change in shopper behavior gets flagged instead of silently degrading results.

A few terms, in plain English

For anyone curious enough to dig a little deeper.

Implicit feedback
Shoppers rarely leave star ratings, but they do click, add to cart, and buy. "Implicit feedback" means learning from those actions instead of asking anyone to rate anything.
Retrieval vs. ranking
Retrieval is the fast, rough first pass that narrows a huge catalog to a short list. Ranking is the slower, more careful second pass that puts the best items in that short list first.
NDCG (Normalized Discounted Cumulative Gain)
A score from 0 to 1 that measures how close a ranked list is to the ideal order, giving extra credit for getting the very top positions right — because a shopper is far more likely to notice item #1 than item #10.
Cold start
The problem of not having enough history about a new shopper (or a new product) to personalize confidently yet. Solved here by falling back to popularity-based recommendations.
Model drift
Over time, shopper behavior changes — new trends, new seasons — and a model trained on old data can quietly get worse. Drift monitoring compares recent predictions against past ones to catch that early.
